# 《植物魔法自动化助手》产品设计手册（重构版·第三版）
**适用版本**：Minecraft 1.12.2  
**模组类型**：AE2 附属  / 植物魔法自动化辅助  
**前置依赖**：Applied Energistics 2（AE2）、Botania（植物魔法）  
**推荐搭配**：任意物品/流体管道模组（Ender IO、Thermal Dynamics、Mekanism、BuildCraft 等）



## 一、产品概述
### 1.1 产品定位
本模组为植物魔法中难以自动化的核心设备提供可被 **AE2 输入/输出总线直接操控的机器方块**。它们不主动索取或推送物品，而是像熔炉、粉碎机等传统科技机器一样，被动接受输入总线的原料注入和输出总线的产物抽取。所有合成逻辑（时序、魔力消耗、催化剂不消耗、位置区分等）封装在机器内部，**原料配方与原版植物魔法完全一致**，不简化、不修改核心机制。

### 1.2 目标用户
+ 喜欢用 AE2 输入/输出总线搭建自由产线的玩家。
+ 整合包作者需要标准化接口的自动化设备。
+ 倾向于“看见物流”而不希望黑盒式一键合成的用户。

### 1.3 核心设计原则
+ **原料一致**：输入原料与植物魔法原版配方完全相同。
+ **被动接口**：机器不从 AE 网络主动索取原料，不上传产物，所有 I/O 由输入/输出总线或管道完成。
+ **无侧面配置**：机器的每一面都同时支持物品输入与输出，实际方向由相连的管道或总线决定。管道可以自由选择抽取或插入，不需要机器端做输入/输出面的区分。
+ **魔力可视化**：需要魔力的机器内置魔力缓存条，显示当前 mana 值，可通过顶部火花接入网络或邻接魔力发射器直接充能。
+ **催化剂透明化**：符文祭坛合成中，催化剂符文随原料一起输入，合成完成后原样返回输出槽，不消耗、不复杂寄存。
+ **无内部活石缓存**：泰拉凝聚台所需活石每次都由外部提供，与原料一同通过输入总线送入，合成完成后产物和活石一并从输出处抽取。



## 二、需求分析与痛点扫描
### 2.1 五大核心痛点
| 原版设备 | 自动化痛点 |
| --- | --- |
| **白雏菊** | 需要 8 个成型面板+独立破坏面板子网，占频道、难扩展 |
| **花药台** | 需精准注水+多步按序投料（种子最后），依赖红石、发射器、悬浮沙漏 |
| **符文祭坛** | 催化剂符文复用困难，常需外部缓存或 Xnet 配合，样板处理复杂 |
| **泰拉凝聚板** | 同物品不同位置难区分，活石放置回收繁琐，魔力不足易卡死浪费原料 |
| **精灵传送门** | 无交互接口，自动化需物品收集器、成型面板等大量辅助块 |


### 2.2 设计思路：把痛点封装成被动机器
不剥夺玩家搭建物流的乐趣，只解决时序、位置、催化剂、魔力保护等核心难题。机器被动接受原料、被动吐出产物，玩家可以自由设计 AE 子网、缓冲、红石条件，极大提升模块化与可维护性。



## 三、功能架构
### 3.1 系统结构示意
```plain
[ME 接口 → 编码样板] → [ME 输入总线] → [机器] → [ME 输出总线] → [ME 网络]
                              ↑ 原料入        ↑ 产物出
                        (流体管道→水)  (魔力输入：火花/发射器)
```

所有机器方块都由 ME 线缆供电（消耗 AE 能量），部分需要水或魔力的从相应接口获取。

### 3.2 机器列表
| 机器名称        | 对应原版设备 | 核心功能 |
|-------------| --- | --- |
| 活石培育器       | 白雏菊 | 消耗 AE 能量，将石头/原木转化为活石/活木 |
| 花药台机器       | 花药台 | 内置水槽，消耗 1000mB 水与配方原料，按时序合成功能花 |
| 符文祭坛机器      | 符文祭坛 | 消耗原料与魔力合成符文，催化剂符文不消耗，合成后原样返回 |
| 泰拉凝聚器       | 泰拉凝聚板 | 消耗原料、活石与魔力合成泰拉钢，活石由外部提供，精确分配放置位置，合成后活石与产物一同返回 |
| 精灵交易器       | 精灵传送门 | 消耗原料与魔力转换为对应精灵物品 |
| 魔力池机器(暂时不做) | 魔力池 | 消耗原料与魔力转化为魔力钢/钻石/珍珠等 |

## 四、各功能详细设计
### 4.1 活石培育器
| 属性 | 说明 |
| --- | --- |
| 输入 | 石头（任意种类，支持 ore:stone）、原木（任意种类，支持 ore:logWood） |
| 输出 | 活石（botania:livingrock）、活木（botania:livingwood） |
| 工作条件 | 消耗 AE 能量（默认 4 AE/t 维持），处理时间 60 秒（与白雏菊一致） |
| 使用方式 | 将 ME 输入总线贴在任意面，标记输入石头/原木；另一面贴 ME 输出总线，模糊标记抽取活石/活木。物品从任何一面进出均可，机器自动识别。 |


### 4.2 花药台机器
| 属性 | 说明 |
| --- | --- |
| 输入（物品） | 配方所需花瓣、花粉、符文等材料 + 任意种子（种子最后步骤自动使用） |
| 输入（流体） | 水，每次合成消耗 1000 mB |
| 输出 | 对应功能花 |
| 内部机制 | 内置水槽（4000 mB），可从任意面接受流体管道输入水。工作流程：`注水(1000mB) → 按序消耗花瓣等材料 → 最后消耗种子 → 产出花`。所有原料需一次性全部就绪，若中途水或原料不足则暂停，补足后继续。 |
| 种子识别 | 机器自动识别种子（通过矿物词典 seed），将其保留至投料序列的最后。 |
| 使用建议 | 用一个 ME 输入总线提供全部原料（含种子），用液体管道提供水；再用一个 ME 输出总线抽取成品花。 |


### 4.3 符文祭坛机器
| 属性 | 说明 |
| --- | --- |
| 输入 | 消耗性原料 + 催化剂符文（两者一起送入，无特殊标记） |
| 输出 | 合成出的符文 + 催化剂符文（原样返回，数量不变） |
| 魔力供应 | 顶部可放置火花连接魔力网络（放置后自动加入支配火花网络接收魔力）。内置 20 万 mana 缓存，每次合成消耗量同原版。 |
| 催化剂处理 | 机器持有一份配方表，知道每个配方中哪些物品是催化剂（通过读取 Botania 配方或 JSON 添加）。合成时，它会检查输入物品，将消耗性材料用尽，催化剂则保留并移至输出缓存，**随产物一起被输出总线抽出，传回 ME 网络**。这样一次合成后，玩家需在 ME 网络中成套管理催化剂，下次合成时由样板再次提供。 |
| 配方歧义解决 | 若两种配方消耗原料完全一致仅催化剂不同，由于催化剂也需输入，样板已包含催化剂信息，自然能区分配方。 |
| 红石控制 | 无特殊红石控制需求，但可使用常规手段（如给输入总线红石信号）来启停生产。 |


### 4.4 泰拉凝聚器
| 属性 | 说明 |
| --- | --- |
| 输入 | 魔力钢，魔力珍珠，魔力钻石 |
| 输出 | 泰拉钢锭 |
| 魔力供应 | 顶部火花座，内置 100 万 mana 缓存，单次合成需 50 万 mana（原版值），魔力不足时自动暂停等待，绝不浪费原料。 |
| 多配方支持 | 支持 BotaniaTweak 等魔改扩展配方，通过 JSON 可定义任意数量的输入物品及放置位置。 |


### 4.5 精灵交易器
| 属性 | 说明 |
| --- | --- |
| 输入 | 交易原料（魔力钻石、魔力钢锭、活木等） |
| 输出 | 对应精灵产物（龙石、元素钢锭、梦之木等） |
| 魔力 | 内置 5 万 mana 缓存，每次交易消耗 200 mana（可配置）。顶部火花座可用。 |
| 配方 | 自动读取 Botania 所有精灵交易配方，并支持 JSON 扩展。 |


### 4.6 魔力池机器
| 属性 | 说明 |
| --- | --- |
| 输入 | 转化原料（铁锭、钻石、末影珍珠、玻璃等） |
| 输出 | 对应魔力产物 |
| 魔力 | 内置 10 万 mana 缓存，每次转化消耗同原版魔力池。支持火花/魔力发射器供能。 |


## 五、合成配方（Crafting Recipes）
以下为模组内各机器的合成表，使用标准工作台合成，原料融合了 AE2 与植物魔法组件。

### 5.1 活石培育器
**形状**：

```plain
LSL
SGS
LSL
```

+ **L** = `botania:livingrock`（活石）
+ **S** = `appliedenergistics2:sky_stone_block`（陨石块）
+ **G** = `appliedenergistics2:engineering_processor`（运算处理器）

**产物**：活石培育器 ×1

### 5.2 花药台机器
**形状**：

```plain
P P
WFC
P P
```

+ **P** = `botania:petal`（任意颜色花瓣，不消耗颜色）
+ **W** = `minecraft:water_bucket`（水桶）
+ **F** = `botania:flower_bag`（花药袋）
+ **C** = `appliedenergistics2:calculation_processor`（计算处理器）

**产物**：花药台机器 ×1

### 5.3 符文祭坛机器
**形状**：

```plain
SRS
RAR
SRS
```

+ **S** = `minecraft:stone`（石头）
+ **R** = `botania:rune`（任意符文，不消耗）
+ **A** = `botania:rune_altar`（符文祭坛） + `appliedenergistics2:formation_core`（成型核心）

**注意**：中间的 `A` 需使用 `botania:rune_altar` 与 `appliedenergistics2:formation_core` 合成一个“符文祭坛核心”中间材料（此处简化表示）。

**产物**：符文祭坛机器 ×1

### 5.4 泰拉凝聚器
**形状**：

```plain
TMT
MCM
TMT
```

+ **T** = `botania:terrasteel_block`（泰拉钢块）
+ **M** = `botania:manasteel_block`（魔力钢块）
+ **C** = `botania:terra_plate`（泰拉凝聚板） + `appliedenergistics2:annihilation_core`（破坏核心）

**同上，C 代表合成中间件**。

**产物**：泰拉凝聚器 ×1

### 5.5 精灵交易器
**形状**：

```plain
QEQ
ELE
QEQ
```

+ **Q** = `botania:quartz_elven`（精灵石英）
+ **E** = `botania:elementium_block`（元素钢块）
+ **L** = `botania:alfheim_portal`（精灵传送门方块） + `appliedenergistics2:logic_processor`（逻辑处理器）

**产物**：精灵交易器 ×1

### 5.6 魔力池机器
**形状**：

```plain
LML
MPM
LML
```

+ **L** = `botania:livingrock`（活石）
+ **M** = `botania:mana_pool`（魔力池）
+ **P** = `appliedenergistics2:engineering_processor`（运算处理器）

**产物**：魔力池机器 ×1

> 注：所有合成表中“+ 某组件”表示需要预先合成一个专用中间物品，配方可在游戏内 JEI 查看。以上合成比例均为 1:1，不消耗其中作为符号的符文、花瓣等（通过配方设置 oreDictionary 实现不消耗）。

## 七、技术实现要点
+ **被动 I/O**：机器实现 `IItemHandler`，所有面均暴露同一个 handler，同时支持插入和抽取。管道侧决定流向。
+ **流体**：花药台机器实现 `IFluidHandler`，自动接收任意面的水注入。
+ **魔力**：通过 `IManaReceiver` 接口接收火花网络或发射器魔力。
+ **Catalyst 处理**：在符文祭坛机器内，参照 Botania 配方中的“催化剂”标记（通过 API 获取），输入物品遍历时将其保留，并在合成完成后放入输出栈。
+ **位置分配**：泰拉凝聚器内部按槽位定义数组，将输入物品依次填充至对应位置，多余的进入原料槽。输出时同样按顺序恢复：产物 + 中心活石 + 四角活石 + 未消耗的额外活石（最多 5 个）原样返回，总量保持。
+ **状态机**：每台机器维护 IDLE → PROCESSING → OUTPUT_FULL 等状态，确保能量、水、魔力不足时正确处理，不吞物。

## 九、总结
本模组以“被动设备”的定位，完美融入 AE2 的输入/输出总线自动化体系，将植物魔法最令人头疼的工艺步骤变成标准化机器，同时不剥夺玩家搭建物流系统的乐趣。催化剂自动返回、活石按需供应、魔力保护停机等设计直击社区长期痛点，配以完整的魔改支持，将为 1.12.2 整合包注入全新的自动化体验。
